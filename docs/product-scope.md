# 产品定位与边界

## 愿景

让 JVM 与 Web 项目能够以清晰、安全、隐私友好的方式接入自托管人机验证，而不必由每个业务系统重新拼装一次性票据、坐标协议、Redis 原子操作和前端交互。

## 定位

ChalSense 是面向 JVM 与 Web 应用的自托管人机验证协议、服务端核心和无框架前端组件。

它首先是安全基础设施，其次才是验证码 UI 库。

## 目标用户

- 需要自托管、不希望依赖云验证码的 Java/Spring 项目。
- 公网或企业内网部署的管理系统、业务系统和开源项目。
- 需要多实例一致状态、一次性验证票据和可审计验证流程的团队。
- 希望保持隐私最小化，同时接受视觉挑战或适度计算挑战的使用方。

## 首版价值主张

- 一套明确、可测试的挑战与票据协议。
- 一个不依赖 Spring 的 Java Core。
- 一个框架无关、可主题化的 TypeScript Web Component。
- 一个 Redis 生产状态实现。
- 一个只负责暴露 Core 能力的薄服务层。
- 一个 Spring Boot Starter，降低 JVM 项目接入成本。
- 可用于集成测试的固定成功、固定失败、过期和重放场景。

## 首版目标

- 支持滑块拼图的生成、展示、轨迹采集和服务端验证。
- 消除原图、显示图、模板、轨迹与滑块位置之间的坐标歧义。
- 验证尝试原子消费挑战，验证成功签发短时一次性票据。
- 票据绑定站点、业务动作和不透明业务上下文摘要。
- 支持 Redis 多实例状态、限流接口和失败关闭。
- 提供可观测指标、结构化错误和不泄露敏感验证数据的日志规则。
- 提供桌面 Pointer Events 和基本触控能力。
- 建立合法素材清单、许可证校验和安全发布流程。
- 从首版提供验证类型扩展边界，但 v0.1 只发布滑块拼图，不提前承诺未实现的 PoW 协议类型。

## 明确非目标

首版不做：

- 云级反欺诈或账户风险平台。
- 设备指纹、跨站追踪或广告标识收集。
- 以“AI”名义包装固定轨迹阈值。
- 管理后台和复杂运营控制台。
- 全语言 SDK、移动端原生 SDK 或小程序 SDK。
- 十几种验证码玩法。
- 文字点选、文化语义识别或大规模字体系统。
- 正式 PoW 挑战；计划在 v0.2 完成设备性能与安全评估后实现。
- 依赖隐藏算法或图片保密获得安全性。
- 替代业务限流、MFA、密码安全和账户保护。

## 安全主张边界

ChalSense 能够：

- 提高低成本自动化和批量请求的成本。
- 提供一次性、场景绑定的验证结果。
- 通过坐标正确性和有限轨迹启发式识别部分明显异常请求。
- 为业务系统提供限流、风险组合和升级验证的可靠输入。

ChalSense 不能保证：

- 验证通过者一定是真人。
- 阻止计算机视觉、自动化浏览器、人工打码或设备农场。
- 单独阻止撞库、刷票、薅羊毛或账户接管。
- 在没有真实数据和持续攻防的情况下达到云厂商风险识别能力。

## 隐私原则

- 默认不采集设备指纹。
- 不收集表单内容、密码、明文账号或与验证无关的页面数据。
- 业务绑定使用由调用方提供的不透明摘要。
- 轨迹采样有明确上限、短期保存并禁止写入普通日志。
- 未来的指纹或增强信号只能作为显式启用、单独说明数据用途的插件。
- v0.1 接入方需要为不能完成视觉挑战的用户提供 MFA、邮件验证或人工协助等替代路径。

## 名称与品牌

- 品牌名：`ChalSense`，含义为 `Challenge + Sense`。
- 代码、仓库和包前缀：`chalsense`。
- 推荐副标题：`Self-hosted human verification for modern applications.`
- 描述中保留 `CAPTCHA` 作为搜索关键词，但不把品牌限制为图片 CAPTCHA。

GitHub 组织、npm scope、Maven 坐标、域名和商标目前只有初步可用性检查，正式公开前仍需完成注册和法律层面的重名核验。
