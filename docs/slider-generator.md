# 滑块生成器与短时资源设计

## 文档状态

- **已批准决策：** D-033 固定 v0.1 生成器、素材与资源发布边界。
- **实现事实：** Core 提供只依赖 JDK 的 PNG 生成器、背景来源 SPI、短时资源发布 SPI，以及确定性和资源上限测试。
- **安全边界：** 挑战图片和资源 URL 可被客户端观察，不是答案保护机制；生成器只能提高自动化成本，不能证明用户一定是真人。

## 生成流程

1. `BackgroundImageSource` 返回一张许可来源明确的本地图片；Core 不联网抓取素材。
2. 生成器在硬尺寸和像素上限内解码并裁剪缩放为固定逻辑画布。
3. CSPRNG 选择缺口位置和左侧拼图片起点，生成带透明通道的拼图片及有可见缺口的背景。
4. 两个 PNG 在内存中完成大小检查后，以一个 `ChallengeResourceBundle` 交给 `ChallengeResourcePublisher`。
5. publisher 只有在两个资源均可读取且过期时间不晚于 challenge 时才返回公开引用；半成功视为失败。
6. Challenge State 写入失败或 ID 冲突时，Core 调用生成器的 best-effort `discard`。清理失败的孤儿资源仍必须依靠 publisher 的硬 TTL 自动过期。

## 固定上限与几何

- 输出背景为 `320 × 180` PNG，拼图片为 `50 × 50` PNG；不把源图尺寸或 EXIF 方向带入线协议。
- 输入图片宽高各不超过 4096，像素数不超过 16,000,000；拒绝非 RGB/ARGB 可表示内容。
- 编码背景不超过 1 MiB，拼图片不超过 256 KiB，整包不超过 1.25 MiB。
- 同一生成器默认最多并发执行可配置数量的生成任务；没有容量时立即失败，由公开层限流和背压处理，不排无限队列。
- 缺口完整位于画布内并保留边距；拼图片起点与目标不重叠。服务端目标、容差和随机选择不进入公开资源元数据。
- 初始容差继续使用 D-014 工作公式并固化 `policyVersion`；D-033 不宣称该数值已经完成误拒率或攻击通过率校准。

## 素材与许可证

- 生产部署必须显式提供素材，不内置来源不明的默认图库，也不把测试图当作生产素材池。
- 每项素材至少记录文件、来源、作者或权利人、许可证、取得日期和允许的修改/再分发范围。
- 测试只使用测试代码程序生成的图像，不引入外部图片、字体、轨迹或数据集。
- 背景来源失败、图片超限、编码失败、资源发布失败均失败关闭，不回退到不受限图片或永久 URL。

## 资源发布 SPI

`ChallengeResourcePublisher` 接收 challenge 标识、站点、绝对过期时间和两个经检查的二进制资源。实现必须：

- 整包发布或明确失败，不返回半套资源；
- 为 URL 使用至少 128 位不可预测标识，且不含 `siteKey`、`action`、答案或业务上下文；
- 允许 Widget 在 TTL 内重复读取图片，资源读取不改变 challenge 的单次 verify 语义；
- 返回准确 media type、像素尺寸和有限长度，HTTP 适配器以后负责 `nosniff`、`no-referrer` 与缓存头；
- 不接收或保存 `pieceTargetX`、`tolerance`、ticket 或 `contextDigest`；
- 在 `expiresAt` 到达后不可读取，并提供幂等 best-effort 删除。

Core 当前不提供内存或文件系统“生产默认实现”。内存实现会破坏多实例一致性，文件系统实现是否共享取决于部署拓扑；两者只可由接入层显式选择。未来对象存储或 Redis 二进制资源实现必须遵守同一 SPI，并单独审查容量、TTL 和故障语义。

## 残余风险

- OpenCV、自动化浏览器和人工打码仍可分析图片；缺口形状和随机位置不是密码学秘密。
- 合法但高度相似或规模过小的素材池会降低攻击成本。
- 生成失败关闭可能被用来影响可用性，因此公开接口仍需限流、容量隔离和指标。
- 图片解码属于复杂输入面；v0.1 默认要求受控本地素材。若未来允许租户上传，必须增加独立隔离、重编码和恶意样本测试，不能直接复用本边界。
