# 合成攻击回归基线

本文定义 v0.1 已知攻击通过率的首个可重复基线。它只刻画当前实现对一小组公开合成输入的行为，不证明通过者是真人，也不代表未知攻击、计算机视觉、自动化浏览器或人工打码的通过率。

## 结论分类

- **实现事实**：`docs/test-vectors/attack-baseline-v1.json` 只含程序编写的固定、线性、贝塞尔状、随机位置和重放输入，不含真实用户轨迹或设备数据；`SyntheticAttackBaselineTest` 通过完整 `ChallengeVerifier` 执行这些输入。
- **实现事实**：当前 Core 只验证轨迹点数、坐标/时间范围、事件顺序、时间单调性、终点一致性和服务端答案；尚未实现经过数据校准的行为启发式。
- **观察事实**：当前基线中，4 个已知精确答案且结构有效的合成轨迹全部取得 ticket（4/4）；1 个超出容差的随机位置被拒绝（0/1 通过）；同一 challenge 的第二次提交返回 `CHALLENGE_UNAVAILABLE`。
- **推论**：位置题能够拒绝未命中答案的低成本猜测，一次性消费能够阻止同一挑战重放，但任意能够求得答案的攻击者可以构造结构有效轨迹通过当前 Core。
- **建议**：在冻结最终 tolerance 或启用轨迹拒绝策略前，增加真实生成图片上的 OpenCV solver、Playwright 自动化轨迹、多种随机位置和并发新建样本，并分别报告样本数与通过率。
- **工作假设**：合成回归首先作为“行为变化报警器”，不把 0% 攻击通过率设为门禁，也不基于这 5 个样本调整 `policyVersion`。

## 机器基线

机器文件：`docs/test-vectors/attack-baseline-v1.json`。每个 runner 必须：

1. 使用独立的新 challenge 执行每个向量，避免前一条的一次性消费影响下一条；
2. 经过完整的站点授权、原子 challenge `take`、轨迹结构、终点和答案检查；
3. 对重放向量在同一 challenge 上连续执行两次；
4. 不把测试轨迹写入生产日志、指标或真实用户校准结果；
5. 若要改变 expected outcome，先说明新增规则、误拒证据、兼容影响和回滚方式，不静默修改基线。

运行 Java 基线：

```text
./mvnw -pl chalsense-core -am -Dtest=SyntheticAttackBaselineTest -Dsurefire.failIfNoSpecifiedTests=false test
```

## 已知限制

- 随机猜测只有一个确定性样本，不能估计理论或经验概率。
- “贝塞尔状”只是手工坐标序列，不代表浏览器自动化或真实 pointer dispatch。
- 尚未运行 OpenCV 缺口识别，也未测批量创建挑战后的求解吞吐。
- 真实用户校准只导出边际粗分桶，不能且不得被还原为攻击轨迹训练集。
- 最终评审必须将误拒区间、已知攻击通过率、无障碍替代流程和运行回滚策略放在一起，而不是单独优化某个数字。
