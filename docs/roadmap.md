# 路线图与完成标准

## 原则

- 路线图表达问题顺序，不承诺日期。
- 每一阶段必须有可验证的安全、体验和工程结果。
- 验证类型数量不是阶段完成指标。

## 阶段 0：设计基线

状态：已通过，评审日期 2026-08-22。通过范围和后续门禁见 `docs/stage-0-review.md`。

### 范围

- 项目定位、目标和非目标。
- 威胁模型与安全主张边界。
- 协议状态机和一次性票据模型。
- 坐标、缩放、轨迹和容差规范。
- Core、Store、Starter、Widget 和薄服务层的依赖边界。
- 隐私、无障碍、素材和许可证政策。
- 基准指标和攻击回归方案。
- 包坐标和发布治理。
- 资源交付、Redis 兼容、状态序列化与 `SiteRegistry`/密钥轮换模型。

### 完成标准

- 新贡献者只读仓库文档即可解释项目为什么存在、首版做什么和不做什么。
- challenge、verify、ticket 的正常、失败、过期、重放和故障路径有状态图或等价规范。
- 坐标换算可以用测试向量独立验证。
- 所有待决策项有明确负责人或进入下一次评审。
- 协议与坐标机器向量可由至少两个独立参考实现产生一致结果，或评审明确接受在 v0.1 脚手架后完成第二实现验证。
- 通过阶段 0 评审后才创建业务代码脚手架。

## v0.1：协议与 Core 可用

### 范围

- Java Core。
- 稳定的协议对象和错误模型。
- 滑块拼图生成与验证。
- Redis 状态和原子挑战/票据消费。
- 站点、动作、Origin 与上下文绑定；静态 `SiteRegistry` 和可重叠轮换的 service credential。
- TypeScript Web Component。
- Spring Boot Starter。
- 薄 HTTP 服务层与 OCI 镜像。
- Testkit 和最小演示应用。
- 合法背景、模板和素材清单。

### 完成标准

- 多实例下可以跨实例创建、验证和消费。
- 并发验证同一挑战时最多一次进入有效判断；同一票据最多一次成功消费。
- 任意抓取点、缩放、常见 DPR 和触控路径有自动化验证。
- 不记录答案、完整轨迹、票据或业务明文上下文。
- Redis 故障策略可测试，高风险默认失败关闭。
- `smart-manage` 可以通过稳定适配层试接入，而无需复制协议逻辑。

## 核心评估指标

### 真实用户体验

- 首次通过率、最终通过率、平均重试次数。
- 错误拒绝率和挑战放弃率。
- 完成耗时 p50、p95。
- 桌面、触控、缩放、高 DPI、弱网和辅助技术差异。

### 攻击成本

- 随机猜测通过率。
- OpenCV 缺口识别通过率。
- 固定、线性、贝塞尔和重放轨迹通过率。
- 并发试探、挑战重放和票据重放结果。
- 单 IP、单站点和跨动作滥用的限流效果。

### 性能与运维

- 生成与验证延迟 p50、p95、p99。
- 单实例吞吐、CPU、内存和 Redis 操作次数。
- 图片与协议载荷大小。
- Redis、时钟、密钥和资源异常下的行为。
